# Перенос проекта из экспортированных файлов

APK v26.1 использует пакет `local.private.maps.review21`, versionCode 395 и
сертификат SHA-256 `3edcb1aabed67020aff5b124ee8ba1e9bd4121674d33b15198eb334e2959efa7`.
Самостоятельное приложение устанавливается под `org.rabochaya.karta`. Прямое
обновление v26.1 требует совпадения пакета и подписи, а также большего versionCode.
Для проверки любого кандидата запусти из `independent-core`:

```sh
python3 security/check_update_identity.py --build-tools /path/to/build-tools/35.0.0 \
  --reference /path/to/v26.1.apk --candidate /path/to/candidate.apk
```

1. Экспортируй из исходного приложения проект в KMZ вместе с доступными вложениями.
2. Если есть экспорт офлайн-карты в MBTiles, подготовь завершённый файл.
3. Сохрани архив и проверь восстановление в новый каталог на локальном диске.

```sh
python3 migration/project_backup.py create --kmz /path/to/project.kmz \
  --mbtiles /path/to/map.mbtiles --out /path/to/project-backup.zip
python3 migration/project_backup.py restore --backup /path/to/project-backup.zip \
  --out /path/to/new-project-directory
```

Для архива без карты опусти `--mbtiles`. Команды используют локальный диск с
поддержкой жёстких ссылок и отказываются перезаписывать существующие пути.
Если отменить восстановление Ctrl+C, команда уберёт свой неполный результат.
В самостоятельном приложении импортируй восстановленный `project.kmz` через
«Проекты и файлы KML/KMZ», затем открой `map.mbtiles` как подложку проекта.
Сверь объекты, вложения и доступные офлайн-тайлы, сохраняя исходное приложение.

Архив хранит экспортированные файлы побайтно. Личные SQLite v26.1, настройки
и кэш, который источник не умеет экспортировать в MBTiles, остаются в хранилище
исходного приложения. Проверена обратимость на тестовых KMZ с вложением и SVG
и на SQLite MBTiles. Импорт персональной выгрузки v26.1 остаётся отдельной проверкой.
