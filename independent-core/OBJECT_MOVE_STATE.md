просмотрены и находятся в manager-forms-qa-2026-10-31/functional-api23/35.
Сам поворот KML не менял. Обычный выбор сохранялся, но папка назначения и
подтверждение исчезали. Следующая реализация пока кандидат для Android CI.

ObjectMoveDraft содержит исходный project, SHA256 XML, process session,
компактные индексы выбора, исходные адрес/подпись назначения и число скрытых
выбранных строк. В Bundle не помещается XML; ограничены число индексов и подпись.
Другой проект или процесс не восстанавливает разрушительное подтверждение.
Изменённый XML показывает прежнее намерение с заблокированной кнопкой; адреса не
перепривязываются. Само восстановление ничего не записывает.

Явный Move передаёт исходный токен в существующую SQLite-транзакцию. Проверка
сохраняется и при изменении проекта после восстановления. Ошибка оставляет
подтверждение, Cancel закрывает его без записи, успешный Move очищает старый выбор.
Модель не применяет перенос и не меняет DOM. Проверка нового процесса пока JVM,
а не отдельное доказательство process-death Android-восстановления.

Локально:21 JVM-набор /81 122 утверждения, ObjectMoveDraft34, host12, QA414 own
classes. Android-кандидат managermove проверяет настоящий destroyed/recreate,
видимый/скрытый выбор, оба направления поворота, Cancel/явный Move,
stale-before со сдвигом адресов, stale-after с транзакционным отказом и чужой
проект с идентичным XML. KML сравнивается по полным XML-токенам/байтам,
вложения — по всем именам и байтам; только синтетические проекты.

Это не полная приёмка менеджера или замены26.1. Выбор папки до подтверждения,
подтверждения удаления/видимости/буфера и полное совпадение с эталоном остаются
отдельными участками. Release gate и статусы требований не изменены.
