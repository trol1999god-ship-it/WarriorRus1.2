# Редактирование описаний в менеджере — 29 октября 2026

## Поведение

Выбрать одну строку флажком → «Действия» → «Изменить описание». Поддержаны папки и отдельные объекты. Редактируется исходный текст description, включая HTML; ссылки не открываются, HTML не исполняется. Никаких запросов или новых разрешений модуль не добавляет. Ввод сохраняет пробелы и переводы строк. Пустой текст очищает редактируемую часть; ограничение — 100 000 единиц UTF-16. Недопустимые символы XML 1.0 отклоняются, ошибка остаётся в диалоге.

Служебные HTML-блоки приложения для вложений не показаны в поле и возвращаются дословно, в прежнем взаимном порядке. Между обычным текстом и блоками не добавляются новые разделители; повторное редактирование не накапливает переводы строк. При настоящем изменении защищённые блоки оказываются после нового текста. Обычные импортированные ссылки, не являющиеся служебными блоками, остаются редактируемым исходным текстом. Это редактор KML/HTML, а не визуальный редактор форматированного текста.

## Сохранность

Загрузка для записи, сверка токена, изменение и сохранение выполняются существующим ObjectTreeWrites под одной SQLite-транзакцией. Нулевое изменение не нормализует корень и не вызывает сохранение payloads. Реальная запись пользуется savePreservingAssets: геометрия, стили, временные метаданные, ExtendedData и файлы проекта не пересоздаются редактором. Настоящее изменение XML делает прежний внутренний буфер выбора устаревшим по существующим правилам.

Поддержаны пространства имён KML 2.2, Google KML 2.0–2.2 и XML без пространства имён, с сохранением префикса нового description. Чужие одноимённые свойства не заменяются. Повторные description/ExtendedData, реальные дочерние XML-элементы, XML-комментарии/инструкции внутри description, повторные идентификаторы вложений и повреждённые/вложенные служебные блоки отклоняются до мутации. Пользовательские описания с зарезервированными маркерами rk-media требуют отдельного разбора; редактор не пытается их исправлять.

## Общее исправление Unicode XML

До исправления Android 6 Transformer создавал ссылки на отдельные половины суррогатной пары, после чего KML не читался. Это воспроизведено настоящим сохранением описания с эмодзи; журнал сохранён как attempt-2-invalid-unicode.txt. Новый KmlXml заменяет дополнительные символы временными ASCII-маркерами только в частной копии DOM, сериализует, восстанавливает настоящие кодовые точки UTF-8 и проверяет XML через SAX до возврата байтов. Исходный DOM не меняется, случайные маркеры не попадают в результат. Копия создаётся через импорт дочерних узлов в новый документ: cloneNode для Document не поддерживается на Android 6. Прежний ABI KmlProject.xml делегирует этому модулю, поэтому исправление относится и к другим путям экспорта/записи, использующим xml().

JVM KmlXmlTests: 31 утверждение; на Android добавлены повторные циклы parse/xml, дополнительные символы в атрибутах, обычном тексте/CDATA, пассивной разметке, неизменность исходного DOM/байтов и отказ недопустимых символов. Проверка JVM также охватывает изолированные суррогаты, служебные последовательности как буквальный текст, DTD/сущности, глубину и размер. Предел итогового XML — 4 МиБ; промежуточного потока — 32 МиБ, глубина — 256. Все экстремальные данные и производительность этих границ на Android не приняты.

Три прежних незавершённых попытки не считаются успешными: наблюдение сообщения через accessibility, исходная ошибка UTF-16 и несовместимое клонирование Document. Их журналы и SHA256 APK сохранены отдельно. Окончательный полный прогон успешен.
