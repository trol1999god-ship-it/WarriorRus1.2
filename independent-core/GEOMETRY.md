# Редактирование координат и контуров

Это собственный модуль следующего промежуточного этапа. Он не закрывает все способы редактирования эталона 26.1.

## Вершины на карте

Добавлены выбор, перенос, вставка, удаление и отмена, работа с незавершённым новым внутренним контуром и существующей подложкой. Подробные действия, ограничения и проверки — `MAP_VERTEX_EDITOR.md`.

## Возможности

Из карточки объекта открывается «Координаты и контуры». Для каждой части MultiGeometry можно отдельно изменить координаты точки/маршрута, внешний или внутренний контур области. Строка редактора — широта, долгота и необязательная высота WGS84. Изменением строк можно добавлять/удалять/переставлять вершины. Внешний контур выбирается отдельно; через «Действия» к области можно добавить внутренний контур или удалить выбранный внутренний контур.

GeometryEdits адресует один элемент coordinates и меняет его текст после полной проверки ввода. Пересоздания Placemark, Polygon или MultiGeometry нет. Сохраняются остальные части, id, свойства высоты/extrude/tessellate, стиль, описание/ссылки на вложения, ExtendedData и неподдерживаемые фрагменты. Новые внутренние контуры используют пространство имён исходного Polygon, включая старое или отсутствующее пространство имён.

Перед записью повторно загружается текущий проект. Хеш геометрии сверяется с состоянием при открытии; изменение геометрии другим действием вызывает отказ записи, сохраняя новый объект и введённый текст. Изменения только метаданных/вложений не вызывают геометрический конфликт и сохраняются из актуального проекта. Запись проекта выполняется существующей транзакцией ProjectStore.

Валидатор вынесен в GeometryCoordinates, FeatureEdits использует тот же код. Для Polygon проверяются минимум три разные географические вершины и замыкание; ±0, ±180° долготы и совпадающие полюса больше не дают ложные «разные» вершины. Не выполняются полная топологическая проверка самопересечений, вложенности отверстий или автоматическая смена ориентации контуров.

## Черновики

Незаписанный ввод сохраняется отдельно в приватном каталоге geometry-drafts при закрытии/уходе/пересоздании редактора. В Bundle длинный текст не передаётся. Файл имеет ограничение размера, версию, идентификаторы объекта/проекта и SHA256; запись идёт во временный файл с sync и заменой. Имя файла строится из числового id проекта и хеша id объекта, а не из введённого пути. Это контроль целостности, не шифрование.

Восстановление черновика не записывает KML автоматически. Повреждённый файл при чтении остаётся на месте. Черновик удалённого контура показывается без возможности ошибочно записать его в другую часть; ввод можно явно скопировать. «Перечитать объект» с подтверждением удаляет черновик. Успешная запись удаляет только совпадающий собственный снимок черновика, оставляя более новый файл; ошибки записи/удаления отображаются пользователю. Прерывание или отказ файловой системы не даёт гарантии сохранения последнего ввода; исходный проект от сохранения черновика не изменяется. Полное управление осиротевшими черновиками и их связь с будущей корзиной ещё не реализованы.

## Проверки и ограничения

GeometryEditsTests исполняется в JVM с реальным DOM: замена маршрута, сохранение стиля/описания/ExtendedData/Model/gx:Track и внутренних контуров, добавление/удаление отверстия, отказ удаления внешнего контура, ошибочный ввод без изменений DOM, конфликт состояния, сохранение новых метаданных, XML-roundtrip, пространства имён. GeometryDraft проверен на полный/крупный ввод, замену, повреждение, изоляцию проектов, безопасные имена и отказ записи. Вместе — 50 утверждений. Общий валидатор — ещё 26 утверждений.

Сценарий Android geometryedit скомпилирован: открытие из карточки, запись в SQLite, сохранение вложения, неверный ввод, восстановление черновика, внутренние контуры и отказ устаревшего сохранения. 28 октября расширенный сценарий исполнен на API23: 68 утверждений пройдены. API35 не пройден; см. ANDROID_QA_2026-10-28.md. Фактические lifecycle, IME, визуальное соответствие и поведение на разных устройствах не подтверждены.

Пока нет сглаживания, разрезания/объединения, полноценного редактирования временных gx:Track и всех остальных операций 26.1. Неподдерживаемые геометрии сохраняются, но не преобразуются в обычные маршруты автоматически.

Структура Polygon/MultiGeometry сверена с первичным справочником KML: https://developers.google.com/kml/documentation/kmlreference#polygon и https://developers.google.com/kml/documentation/kmlreference#multigeometry . Это не заменяет проверку совместимости экспорта в целевых приложениях.

## Действия с отдельными вершинами (28 октября)

«Действия» → «Редактировать вершины» открывает список вершин выбранной части. Можно изменить одну вершину, вставить новую перед/после, поменять порядок соседних строк или удалить с подтверждением. У точки доступно только изменение координат. Для полигона замыкающая копия первой вершины не предлагается отдельно; замыкание обновляется общим валидатором. Изменяется только ввод; для записи объекта нужна кнопка «Сохранить». Отмена диалога сохраняет исходный ввод.

GeometryVertices выполняется без Android и не обращается к проектам/файлам/сети. Он проверяет весь результат до возврата, включая минимальное число разных вершин и ограничения общего валидатора. Сохраняются числовые координаты/высоты остальных вершин; текст нормализуется (десятичные числа, высота 0 при её отсутствии). Для выбора нужен уже допустимый список. Для работы на карте теперь есть отдельный режим, описанный в MAP_VERTEX_EDITOR.md.

36 JVM-утверждений проверили операции, замыкание, высоты, неверный ввод, границы индексов, минимальное число вершин и лимит 10000 строк. Android geometryedit расширен и исполнен на API23: 68 утверждений пройдены. API35, физический телефон и полная равноценность остаются непроверенными.
