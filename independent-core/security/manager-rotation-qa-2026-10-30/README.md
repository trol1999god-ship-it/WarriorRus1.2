managerrotation использует свежие синтетические проекты, настоящую IME,
UiAutomation rotation 0/90 и требует другой Activity с destroyed=true у старой.
Восстановление текста/диапазона 3..8 и выбора проверяется после этого, а не
после скрытия клавиатуры. После запроса IME проверяются её реальные окна,
видимая строка ввода и полностью доступные Save/Cancel; Cancel нажимается
событиями DOWN/UP. Автоматическое открытие каждой сторонней IME не принимается.

Проверены восемь случаев: имя корневой метки и описание вложенной метки ×
Cancel/Save/stale-before/stale-after. Исходные project/token/XML-адрес сохраняются;
при изменённом XML Save выключен, при изменении после восстановления транзакция
отказывает и текст остаётся. Cancel не меняет KML/вложения; явный Save меняет
целевое свойство, остальные XML и bytes вложений сохраняются. Дополнительно
проверены два выбранных объекта (один вне открытой папки), её восстановление и
полная очистка выбора после изменения XML. Старые force-stop/reopen проверки
выполнены в этом же полном прогоне; обычный выбор после нового процесса пуст.
