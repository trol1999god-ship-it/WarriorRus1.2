# Вершины на карте

Из карточки объекта откройте «Координаты и контуры», выберите часть маршрута или контур и нажмите «Редактировать на карте». Переключение обратно — «Координаты списком». Это два представления одного незаписанного ввода.

| Действие | Поведение |
| --- | --- |
| Касание вершины | Выделяет ближайшую вершину жёлтым маркером |
| Перетаскивание выделенной/найденной вершины | Меняет широту и долготу после отпускания пальца, сохраняет её высоту |
| «Добавить», затем касание карты | Вставляет вершину после выбранной, либо в конец без выделения; высота новой вершины — 0 м |
| «Удалить» | Удаляет выбранную вершину после подтверждения, с проверкой минимального размера геометрии |
| «Шаг назад» | Отменяет одну принятую операцию с вершиной |
| Перетаскивание свободного места | Перемещает карту, не меняя геометрию |
| Два пальца, в том числе с первым касанием вершины | Передают жест карте для масштаба; незавершённый перенос вершины отменяется |
| «Охват», «+», «−» | Меняют только видимую область карты |
| «Сохранить» внизу редактора | Проверяет весь выбранный контур и конфликт геометрии, затем записывает проект существующей транзакцией |

Для метки с единственной вершиной доступны её выбор и перенос; добавление и удаление отключены. Минимум маршрута — две вершины, области — три разные географические вершины. Замыкающая копия первой вершины не предлагается отдельно; при записи её координаты и высота обновляются вместе с первой вершиной.

Новый внутренний контур можно начать прямо на карте через «Действия» → «Добавить внутренний контур». Пустой/неполный контур остаётся черновиком; пока нет трёх разных вершин, проект не записывается. После сохранения новый внутренний контур остаётся выбранным.

## Данные и отмена

`GeometryMapState` хранит только выбранную часть и не обращается к XML, файлам или сети. Перенос предварительно отображается, но становится действием только по ACTION_UP. ACTION_CANCEL и отпускание вне карты отменяют предварительное положение. Недопустимая операция не меняет ввод и не попадает в историю.

История ограничена 32 действиями и 4 миллионами символов снимков. Она сохраняется при переключении карта/список, пока текст не менялся отдельно. После записи, смены части или новой Activity/процесса начинается новая история. Принятые координаты при этом восстанавливаются из приватного черновика, а не из истории отмены. Смена части с несохранённым вводом требует явного подтверждения отмены.

Завершённые действия сразу обновляют обычный `GeometryDraft`. Он не является записью KML. При полной отмене до исходного текста собственный устаревший черновик удаляется. Очистка после сохранения и полной отмены сверяет снимок: завершившийся старый обработчик записи не должен удалить уже обновлённый файл черновика. Это не отдельный многопользовательский менеджер черновиков; файл по-прежнему один на объект проекта. Повреждённый чужой/непрочитанный файл автоматически не удаляется.

При сохранении повторно загружается актуальный проект, используется прежний token геометрии и `GeometryEdits`. Соседние части, стили, ExtendedData, ссылки и файлы вложений не пересоздаются. Изменение геометрии другим действием по-прежнему отклоняет устаревшую запись. Автоматического применения восстановленного черновика нет.

## Карта и ограничения

Подложка — существующий LocalMapView: выбранные для проекта онлайн-карты с прежним разрешением сети/кешем, локальная MBTiles либо встроенная обзорная карта. Отдельного сервиса объектов, геолокации и новых разрешений нет. Вход/выход из режима карты открывает/закрывает её читатели; уход в фон приостанавливает запросы. Редактор вершин не передаётся в построитель запросов тайлов.

Редактирование на карте ограничено Web Mercator до ±85.05112878°. Полярный ввод не исправляется и не обрезается: для него остаётся список координат. Прежняя проверка минимума/диапазона не является полной топологической проверкой самопересечений и вложенности внутренних контуров. Сглаживание, разрезание/объединение, временные gx:Track и полная равноценность 26.1 остаются отдельными незавершёнными задачами.

## Проверка

Новая JVM-проверка GeometryMapState включает операции, точное восстановление текста, минимальные размеры, высоты, замыкание, ограничение истории, реальные DOM-изменения без потери соседних данных и условную очистку обновлённого черновика.

Android-сценарии `geometrymap` и `geometrymapreopen` образуют пару: первый создаёт синтетические данные и оставляет черновик; драйвер действительно останавливает процесс, второй восстанавливает и записывает его. Между ними данные тестового пакета не очищаются. В остальные сценарии передаётся очищенный тестовый пакет. Восстановление без предшествующего успешного сценария в том же запуске запрещено драйвером.

Проверяются настоящие касания через UiAutomation, масштаб двумя пальцами с началом на вершине, перенос карты, ACTION_CANCEL, отмена, минимум вершин, новый внутренний контур, SQLite, высоты, стили, импортированная относительная HTML-ссылка, управляемая запись вложения и два двоичных файла. Фактические результаты текущего прогона сохраняются в `security/vertex-map-qa-2026-10-28/`.

Это промежуточный этап самостоятельной реализации. Новый установочный выпуск замены 26.1 не создавался. API35/Android16, физический телефон и все состояния поворота экрана этим этапом не приняты.

## Результаты текущей сборки

На API23/x86 без KVM прошли **11 сценариев, 861 утверждение**: новая пара geometrymap (101) / geometrymapreopen (16), прежний редактор geometryedit (70), launcher (123), coordinates (46), catalogscreen (28), binary (2), independence (443), offlineformats (6), cachewrites (10), cacheexport (16). Это один полный успешный прогон одного финального production APK. SHA256 и длительности — security/vertex-map-qa-2026-10-28/results.json. Все файлы тестов синтетические.

JVM: 80393 успешных утверждения. Из них GeometryMapState — 52: модель операций, DOM-сохранность и условная очистка черновика. Production Java/API23, D8 min-api23 и независимая сборка прошли; в DEX 324 собственных класса, нет отсутствующих/посторонних классов, ABI-заглушек и нативных библиотек. Манифест не менялся: только INTERNET.

При просмотре новых экранов проверены выбор части, маркеры, кнопки, состояние несохранённого ввода и отсутствие устаревшего уведомления об успешной записи после нового изменения. Для старого launcher-сценария устранено использование заменённого вида карты: текущий вид выбирается на UI-потоке после завершения загрузки, проверяются его прикрепление и фактическая доставка касаний. Прежняя проверка координаты нажатия сохранена.

API35/Android16 и физический телефон на этом этапе не испытывались; прежний отказ нестабильной среды API35 описан отдельно в ANDROID_QA_2026-10-28.md. Поворот во всех состояниях, внезапное отключение питания, полная топология областей, все форматы и полная равноценность 26.1 не приняты.
