# Поиск по описаниям — 28 октября 2026

В диалоге «Поиск и фильтры» добавлено поле «Искать в»: «Название», «Описание», «Название или описание». Прежние сохранённые настройки без этого поля по умолчанию продолжают искать только по названию. Некорректные настройки безопасно сбрасываются. Параметр сохраняется отдельно для каждого проекта вместе с запросом и остальными фильтрами; выбор строк после перезапуска очищается.

Запрос остаётся буквальной подстрокой длиной до 256 кодовых единиц UTF-16. Регистр не учитывается, Unicode приводится к NFC, «е/ё» совпадают. Последовательности пробельных символов, включая неразрывный пробел, приводятся к одному пробелу; пробелы по краям не учитываются. Это применяется и к названиям, и к описаниям. В объединённом режиме достаточно совпадения в одном поле: конец названия и начало описания не образуют общий текст.

Индекс читает только непосредственные KML `description` каждого объекта или папки. Описание родителя не наследуется детьми; чужие пространства имён и вложенные `ExtendedData/description` не подмешиваются. Предварительный индекс строится в рабочем потоке. Исходные адреса дерева, порядок XML, стили, координаты, высоты и вложения не изменяются. Фильтры по типу/видимости, вложенность, сортировка и операции над выбором используют те же исходные адреса, что и раньше.

Для обычного HTML-текста описания используется собственная текстовая проекция, без WebView: форматирующие теги убираются, блочные элементы и `br` разделяются пробелами, комментарии, `script`, `style`, `template` и атрибуты не индексируются. Поэтому подпись ссылки находится, а её `href`, `src` изображения и `alt` не становятся текстом результата. Декодируются десятичные/шестнадцатеричные числовые ссылки на допустимые символы Unicode и ограниченный набор именованных сущностей: `amp`, `lt`, `gt`, `quot`, `apos`, `nbsp`, `ndash`, `mdash`, `laquo`, `raquo`, `hellip`, `copy`, `reg`. Декодирование однократное; неизвестные и недопустимые сущности остаются буквальным текстом. Индекс не обрезает длинное описание.

Это проекция для поиска, а не полная реализация HTML5 или совпадение с любым браузерным отображением повреждённого HTML. Поиск не открывает ссылки, не загружает изображения, не исполняет скрипты, не читает содержимое файлов вложений и не обращается к сети. Произвольный XHTML внутри XML не объявлен отдельным поддержанным форматом описания. Даты, координаты, дополнительные поля и содержимое документов пока не входят в область поиска.

«Отмена» сохраняет применённые параметры, «Сбросить» возвращает режим поиска по названию. Переход в папку/вверх и снятие активных фильтров кнопкой назад также сбрасывают поисковую область к названию, сохраняя прежнюю сортировку и настройку папок вначале. Пустой запрос показывает всю текущую область независимо от выбранного поля.
