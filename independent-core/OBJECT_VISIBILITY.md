# Массовая видимость KML — 28 октября 2026

## Команды менеджера

В меню добавлены «Показать выбранные» и «Скрыть выбранные». Они работают с любым выбором строк, в том числе из разных папок и скрытым текущим фильтром. Перед записью показываются число выбранных строк, число строк вне результата, количество меняемых собственных свойств и сколько строк/папок изменит эффективную видимость KML с учётом потомков.

Команда меняет собственную видимость каждого явно выбранного элемента. Если выбраны и папка, и её ребёнок, оба применяются; выбор ребёнка не отбрасывается как избыточный. При выборе только папки её потомки меняют эффективную видимость через наследование, а их собственные значения остаются прежними. Например, показ папки не отменяет самостоятельное скрытие одного из её детей.

Родительские папки автоматически не раскрываются. Показ ребёнка под скрытым предком может оставить его скрытым; подтверждение отдельно сообщает число таких выбранных элементов. Если собственная видимость уже включена, менеджер объясняет причину без записи. Для показа всей группы следует выбрать её папку; изменение родительской папки может затронуть и другие её элементы, поэтому оно должно быть явным.

Подтверждение можно отменить без изменения данных. Если собственные значения уже соответствуют команде, XML и payloads не перезаписываются. Поэтому такая команда не делает внутренний буфер копирования устаревшим. Реальное изменение XML по-прежнему требует заново заполнить ссылочный буфер.

## Семантика и сохранность

`ObjectVisibility` — общий независимый от Android читатель/редактор видимости. Значения KML `0` и `false` означают скрытие; `1`, `true` и отсутствие свойства — видимость. По краям читаемого значения убираются обычные пробелы. Неизвестные значения сохраняют прежнее поведение чтения — видимость; при отсутствии необходимого семантического изменения они не переписываются. Новые значения записываются в виде `0`/`1`.

Фильтр списка и существующий ABI `KmlProject.visible(Element)` используют один читатель. В owned-smali изменено только тело этого метода: оно делегирует чтение в ObjectVisibility; сигнатура сохраняется. Это исправляет импортированное `false`, которое предыдущий читатель ошибочно показывал. `effectivelyVisible` карты продолжает проверять всех предков, теперь используя согласованную семантику. API-заглушки в APK не упаковываются.

Свойства в неизвестном пространстве имён не принимаются за KML visibility и не меняются. При нескольких свойствах KML visibility у выбранного элемента операция отклоняется до изменения DOM. Для чтения такой неоднозначный элемент считается скрытым, если одно из свойств явно скрывает его. Полноценное исправление повреждённого KML не входит в команду.

Предварительный расчёт проверяет снимок дерева и все адреса до изменения. Он учитывает полное поддерево, исходную и предполагаемую видимость, не меняя DOM. Запись касается только необходимых свойств visibility: существующий элемент меняет текст, недостающий создаётся после name в том же пространстве имён/префиксе. Геометрия, высоты, внутренние контуры, идентификаторы, стиль, ссылки, описания и записи вложений не пересоздаются. Все файлы проекта сохраняются, включая скрытые/неиспользуемые.

`ObjectTreeWrites` начинает SQLite-транзакцию до загрузки актуального проекта и проверки снимка. Несовпадение снимка, ошибка адреса или сохранения не должны оставлять частичную запись XML/файлов. При нулевом изменении сохранение payloads и нормализация корня не вызываются. После реальной записи экранный выбор снимается, индекс перестраивается, а при возврате карта перечитывает видимые объекты.

Это видимость KML, а не попадание в экран/масштаб, фильтр времени, Region/LOD, активность отдельной подложки или наличие загруженного тайла. Изменение собственных значений не отменяет эти ограничения. Отдельного управления слоями и автоматического раскрытия предков пока нет.
